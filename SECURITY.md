# Security and responsible disclosure

Do not file a public issue containing patient metadata, private URLs, access tokens, proprietary input files, unpublished scientific results, or identifying study details.

If sensitive content has been committed, treat it as potentially exposed: notify the repository owner through a private channel, revoke affected credentials, restrict access to the repository if needed, and follow institutional incident-response procedures. Deleting the latest version does **not** erase Git history or forks.

Before changing any private research repository to public, complete `docs/PUBLIC_RELEASE_CHECKLIST.md` and obtain the project's written data-release authorization.
